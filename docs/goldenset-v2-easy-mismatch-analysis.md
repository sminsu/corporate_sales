# goldenset v2 mismatch — difficulty=easy 63건 원인과 대응

입력은 `goldenset-v2-mismatches.csv` 452건 중 `difficulty=easy` 63건이다.
mismatch 라고 전부 오답은 아니라서 질문·정답 SQL·에이전트 SQL 을 하나씩 대조했다.
실제로 고쳐야 할 것은 아래 다섯 갈래였고, 나머지는 골든셋 컨벤션 차이다.

대상 모델은 gemma4·gpt-oss 급 로컬 LLM 이다. 이 모델들은 프롬프트에 있는 SQL을
거의 그대로 베끼고, 프롬프트 안에서 신호가 엇갈리면 더 눈에 띄는 쪽을 고른다.
그래서 대응도 "모델을 더 잘 설득한다"가 아니라 **틀린 재료를 아예 안 준다** 쪽이다.

## 1. 참고 SQL 템플릿이 통째로 나갔다 (29건)

가장 큰 원인이다. Verified Query(참고 SQL)는 컬럼이 고정된 완제품인데, 매칭
게이트가 어휘 겹침(태그 1개당 +3점)과 임베딩 유사도만 봤다. 같은 업무 영역
단어를 쓰기만 하면 전혀 다른 답이 나갔다.

| 질문 | 붙은 VQ | 실행된 것 | 정답 |
|---|---|---|---|
| 2026년 특수채권편입**연체료**를 **연체채권 종류** 기준으로 | `special_debt_by_asset_quality` | 전 기간 × 자산건전성 33행 | 연체채권종류별 3행 |
| **카드등급별** 2025-06-30 **할부연체원금** | `card_delinquency_by_grade` | 카드등급별 연체율 | tddaa3l01.할부연체원금 |
| **회원자격별** 현재 **통합한도금액** | `corporate_limit_status_at_month` | 기업별 한도소진율 목록 | tbdaaat03 회원자격별 |
| 2026년 7월 **소기업**으로 분류된 기업고객 수 | `new_customers_by_month` | 최초등록년월일 기준 신규고객수 | tbdaa1d12.소기업여부 |

경로는 두 개였다. 하나는 VQ 가 매칭돼 그대로 실행된 것, 다른 하나는
`## 참고 SQL 예시` 로 프롬프트에 붙어 모델이 베낀 것이다. 둘 다 막았다.

**대응** — `text2sql_agent/v2/vq_output_guard.py` 신규.
"이 VQ가 질문이 요구한 값을 실제로 내놓는가"를 네 가지로 본다.

1. **기간** — 질문에 절대 기간(2024년, 202607, 상반기)이 박혀 있는데 VQ에 기간
   파라미터도 시간 필터도 없다. `special_debt_by_asset_quality`(전 기간 집계),
   `daily_sales_amount` 가 여기 걸린다.
2. **대상 정의 개념** — VQ의 name·question·tags 에만 있는 한정 개념(신규 가입,
   무실적, 폐업·해지, 해외)을 질문이 요구하지 않았다. description 은 보지 않는다.
   내부 구현 설명이라 개념어가 필터가 아니라 계산 결과로도 등장한다.
3. **축** — 질문이 "X별 / X 기준으로" 로 축을 지목했는데 VQ의 GROUP BY 에 없다.
4. **지표** — 질문이 스키마 컬럼명을 그대로 불렀는데 VQ SQL 에 그 컬럼이 없다.

거부는 답을 포기하는 게 아니라 LLM 생성 경로로 내려보낸다는 뜻이다.
연결 지점은 `workflow._verified_query_matches_intent()`(실행 경로)와
`schema.find_relevant_queries()`(프롬프트 예시 경로) 두 곳이다.

## 2. 그룹핑 축 어구가 기업명으로 바인딩됐다 (3건)

```sql
-- "회원자격별로 현재 기준 통합한도금액을 보여줘" 가 만든 SQL
AND ('회원자격별로' = '__ALL__' OR ... LIKE '%회원자격별로%')
```

`_extract_company_name_by_rule()` 이 `^(이름)\s*(?=현재|20\d\d년|...)` 패턴으로
시간 표현 앞 토큰을 기업명으로 집었다. 결과는 0행이다. "X별/X별로/X 기준으로"
는 축을 지목하는 말이지 이름이 아니다.

**대응** — `workflow._is_grouping_axis_phrase()` 를 이름 후보 검증에 추가.
`_extract_company_name_by_rule()` 과 `_extract_merchant_name_by_rule()` 양쪽.

## 3. 기업영업 스코프 필터가 빠졌다 (18건)

정답 452건 중 **276건**이 `개인기업구분코드 = '2'` 를 쓰고 다른 값은 한 번도
안 쓴다. 에이전트는 **99건**에만 붙였다. 질문에 "법인"·"기업" 이라는 말이 없으면
개인까지 함께 세서 행 수와 금액이 전부 어긋난다.

v1 규칙이 "법인·기업 **대상 질의는** 개인기업구분코드가 있는 테이블에서만 = '2'
조건을 붙인다" 라 조건부였다. 이 에이전트의 조회 대상 자체가 기업영업이므로
기본값으로 뒤집었다.

**대응**
- `v2/sql_contract.py AMBIGUITY_RULES_V2` — "질문이 개인·전체를 명시하지 않는 한
  항상 붙인다" 로 교체.
- `workflow._corporate_scope_rule()` — 프롬프트에 `## 조회 대상 범위 (기업영업)`
  절을 만들고, 선택된 테이블 중 그 컬럼을 **실제로 가진 것만** 이름으로 적는다.
  컬럼이 없는 테이블(tmdaa5e11, tbdaadt01 등)에는 조건을 만들지 말라는 기존
  규칙과 충돌하지 않게 하려면 목록을 같이 줘야 한다.

## 4. tbmaisd06 의 "2024년" 이 편입일로 해석됐다 (7건)

```sql
-- 에이전트                                 -- 정답
WHERE SUBSTR("특수채권편입기준년월일",1,4)='2024'   WHERE "기준년" = '2024'
```

grain 은 `기준년 × 특수채권관리번호 × 고객` 인데 `기준년` 의 format 이
`STRING_DATE` 로 되어 있어 연도 문자열이라는 게 프롬프트에서 드러나지 않았다.

**대응** — `기준년` 의 `format: YYYY`, `role: snapshot_date`, 설명 보강.
물리 `primary_time_dimension`(특수채권편입기준년월일)은 그대로 둔다. 연 단위 조회
컬럼은 `accumulation_policy.query_time_dimension` 이 이미 선언하고 있고,
프롬프트에 `tbmaisd06: 매년 · 기간 컬럼 기준년(YYYY)` 과
"월/일 요청도 적재 기준 조건은 `기준년`의 YYYY로 축약합니다" 로 렌더된다.
빌드 스크립트의 `TIME_AXIS_FIXES` 에 넣어 재생성해도 유지된다.

## 5. 정답 테이블이 후보에 아예 못 올랐다 (10건)

`docs/integration.md` 가 "다음 병목"이라고 적어 둔 지점이다. 원인 두 개를 찾았다.

**5-1. authoritative 계약의 조기 반환.** `named_corporate_limit_status_at_month`
는 `entity_binding: {parameter: 기업명, required: true}` 인데 `match.required` 가
`["한도"]` 한 단어뿐이다. 그래서 이름이 없는 "현재 기준 CA한도별 CA한도금액" 까지
잡아 `tbdaa1d12` 를 authoritative 로 못박고, 점수 계산을 통째로 건너뛰었다.
`CA한도금액` 을 실제로 가진 `tbdaaat03` 은 후보에도 못 든다.
→ `_contract_entity_bindings_available()`: required 엔티티를 질문에서 못 뽑으면
authoritative 로 쓰지 않는다.

**5-2. 정확한 컬럼명 일치가 동의어와 같은 값이었다.** 질문이 `CA한도금액`,
`부서사업장이용한도금액`, `가맹점월승인한도금액` 처럼 컬럼명을 그대로 부르는 건
동의어 겹침과 격이 다른 증거인데, 둘 다 3점짜리 `column_hits` 로 묶여 최대 12점
이었다. semantic attribute 점수(36)에 밀려 그 컬럼이 없는 테이블이 이겼고, 모델은
`output_contract` 4번 규칙("가장 가까운 컬럼을 골라")대로 없는 값을 대체했다.
→ 정확 일치 컬럼 1개당 40점(최대 2개).

452건 전체에서 정답 테이블 커버리지:

| | 정답 테이블 전부 후보에 | 적어도 하나 후보에 |
|---|---|---|
| easy | 39/63 → **56/63** | 42/63 → **59/63** |
| medium | 39/130 → **51/130** | 87/130 → **109/130** |
| hard | 103/259 → **122/259** | 223/259 → **249/259** |
| 전체 | 181/452 (40%) → **229/452 (51%)** | 352/452 (78%) → **417/452 (92%)** |

어느 난이도에서도 내려가지 않았다.

### 곁다리: 랭킹이 18초였다

5-1 을 고쳐 조기 반환이 사라지자 `_rule_rank_tables()` 한 번이 **18초**가 됐다.
`phrase_in_text()` 가 호출마다 패턴을 새로 컴파일하는데, 구분자 클래스
`[^0-9A-Za-z가-힣_]` 가 한글 음절 11,172자를 포함해서 컴파일당 5ms 쯤 걸린다.
질문 하나가 컬럼·동의어 6,000여 개를 대조하고(v2 가 동의어 3,243개를 유도했다)
서로 다른 패턴이 3,000개를 넘어 `re` 내부 캐시(512개)가 계속 밀려났다.
→ `_phrase_pattern()` 에 `lru_cache`. 18,000ms → **11ms**.

프롬프트 조립 전체가 같은 매처를 쓰므로 이 캐시는 랭킹 밖에서도 효과가 있다.

## 추가로 필요한 정보

1. **`tbdaaat03.회원자격코드` 의 코드 목록.** 정답이 166행이다. 코드 컬럼치고
   많아서, 실제 코드값 사전이 있어야 "회원자격별" 결과가 맞는지 검증할 수 있다.
2. **등급/그룹 코드 컬럼 코드북** — `CA한도등급코드`, `통합한도등급코드`,
   `CA요율그룹구분코드`, `할부요율그룹구분코드`. 질문의 "CA한도별",
   "통합한도 기준으로" 가 금액 컬럼이 아니라 이 등급 컬럼을 가리킨다는 걸
   value_semantics 로 못박아야 같은 혼동이 안 난다.
3. **기업 스코프 예외 테이블.** `개인기업구분코드` 가 없는 가맹점계 테이블
   (tmdaa5e11, tbdaadt01, tbdaadb17, tbdaabf07)에서 기업영업 모수를 어떻게
   한정하는지. 지금은 조건을 안 붙인다.
4. **`tbdaadb17`·`tbdaabf07` 의 업무 별칭** — "업종 마스터", "MCC 마스터",
   "업종코드 사전" 등 현업이 실제로 쓰는 말.
5. **출력 컬럼 계약** — 위 "골든셋 컨벤션" 표의 규칙. 특히 (a) 그룹 필터가 걸린
   집계에서 필터 컬럼을 SELECT 에 남기는지, (b) "A와 B" 를 물으면 같은 계열의
   C 까지 붙이는지.
